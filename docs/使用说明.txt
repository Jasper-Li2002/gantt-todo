【v2.6.0 新增「检查更新」（只提示，不自动替换）】2026-10-27
1. 入口两处：「⋯ 更多 → 版本 → 检查更新…」，以及托盘图标右键 →「检查更新…」。
2. 只做提示，不做静默替换：查到新版本后告诉你版本号和更新说明，
   点「是」用默认浏览器打开下载页，自己下载覆盖即可。
   不做自动替换的原因：万一新版本有问题，用户不该莫名其妙发现程序变了。
3. 更新源怎么配（不配也能用）：
   打开 %APPDATA%\TodoCalendar\update.json，写
       { "url": "更新源地址" }
   支持三种地址：
     · http(s) 指向的 version.json：{"version":"2.6.1","page":"下载页","notes":"说明"}
     · GitHub Release API（仓库公开时）：
       https://api.github.com/repos/<用户名>/<仓库>/releases/latest
     · 本地路径或共享盘路径，例如 \\共享盘\gantt-todo\version.json
       （内网分发走这个最稳，不用连外网）
   留空 = 未配置：点「检查更新」会明确说明没配源，并询问是否打开下载页。
4. 配好源之后：每次启动静默查一次（每天最多一次），有新版本弹一次托盘气泡，
   点气泡直接打开下载页；同一版本可以选「忽略此版本」，之后不再提醒。
5. 自检命令（不用开窗口）：
       TodoCalendar.exe --check-update --url "更新源地址"
   结果写到 %TEMP%\todocal-update.txt。
6. 提醒一下：本程序不联网，只有你主动点「检查更新」或配了更新源时才会发请求。

【v2.5.8 开机自启：开关搬到「⋯」菜单，开机静默起在托盘】2026-10-27
1. 背景：原来的开机启动开关只在「托盘图标右键菜单」里，很难发现，实际从没开启过。
   现在「⋯ → 开机自启」直接可见，带勾选框和实时状态。

   现在改由 OnHandleCreated 兜底（已实测：静默启动 75 秒后提醒正常触发）。

   重启或开机后不会把同一天的提醒再弹一遍。

   - 文件夹挪走后旧路径失效、开关"看着开着其实早废了"；现在启动时自动改写为当前路径。
   - 点提醒气泡可以直接打开窗口。

【v2.5.7 「今天」看不出来 —— 改成描边 + 实心数字】2026-10-26
1. 现象：想找今天是几号，颜色跟底色几乎一样，扫一遍日历定位不到。
2. 原因两条：
   a) 今天格用的是整格填色 #f7f8ff，跟白底（#fff）差不到 3%，肉眼分不出；
      而任务条也是填色块 —— 两种填色叠在一起，今天就被淹没了。
   b) 深色模式下 --accent 是浅紫 #9aa4ff，数字却是白字，对比度只有 2.4:1
      （正文要求 4.5:1），数字直接糊在底色里。
3. 改法（不动配色体系，仍是方案 D 的靛蓝/浅紫）：
   a) 今天格改用「1.5px 靛蓝内描边」标记，而不是整格填色 ——
      任务条是填色、今天用轮廓，两者不再混淆。
   b) 数字改成 20px 实心圆底：浅色下靛蓝底白字（5.8:1），
      深色下浅紫底深字（7.7:1），两种主题都达标。
   c) 侧栏迷你月历的「今天」同样修了深色对比度。
   d) 导出 PNG 里绘制今天圆点的那段也跟着改了字色，导出图不再出现白字糊紫底。
   e) 补了今天的 hover 反馈（原来被 .day.today 盖掉了，鼠标移上去没反应）。
4. 优先级已处理：今天放在所有 .day 变体之后定义，周末/工作日/非本月/法定假日
   这四种状态下描边都不会被盖掉（已断言验证）。

【v2.5.6 修复：列表视图不停闪烁刷新】2026-10-23
1. 现象：切到「列表」后整张列表反复闪动、像在一遍遍重新入场。
2. 根因（两处，都只在列表存在，月视图没有，所以只坏这一个视图）：
   a) 列表项样式写的是 animation:slideIn .22s ease both —— fill:both 会让动画结束后
      把 transform 永久留在元素上。20 条待办就是 20 个独立合成层压在滚动容器里，
      WebView2 真机渲染时会持续重绘。
   b) renderList() 每次都用 innerHTML='' 全量重建，任何一次重渲染（轮询、点选、
      切筛选）都会让整张列表重跑一遍入场动画。
3. 处理：
   a) 去掉 fill:both，改成动画只在 ul.list.anim 上生效；动画结束由 JS 摘掉这个类，
      元素不留 transform。
   b) 入场动画只在「刚切进列表」那一次播，之后重渲染一律不动画。
   c) renderList 增加内容签名比对：数据没变就直接 return，不重建 DOM。
      勾选、改筛选、增删改这类真实变化签名会变，照常重建（已验证 11 项行为）。
4. 数据无影响，本次只改渲染。

【v2.5.2 AI 稿重写能力修正】2026-10-23
问题：AI 稿和事实清单看起来几乎一样，只是换了几个词。
根因有两个，都在我们这边：
  A. 提示词要求"按清单原有的 ■/· 段落逐条展开"，等于命令模型照抄格式；
  B. 日报素材太空（今日完成 0 项），模型没有可加工的内容。
改法：
1. 提示词重写：事实层仍然锁死（不得新增任务、不得改日期/百分比、不得编造原因），
   但表达层要求重写成连贯段落，禁止出现 ■ 和 · 清单，并给了"输入→正确输出"的示例对照。
   这是最有效的手段——大模型对"不要照抄"这类否定指令不敏感，给样例才有用。
2. 生成温度 0.3 → 0.65。太低会趋于复述原文，改写类任务 0.5~0.7 合适。
3. AI 模式下新增「补充一句（可选）」输入框：你写一句"今天主要在等客户反馈"，
   会随清单一起发给模型，AI 才有素材可写。这是提升质量最直接的一步。

【运行环境】
- Windows 10/11 64 位
- 需要 .NET 10 桌面运行时（本机已安装，可直接运行）
- 需要 Microsoft Edge WebView2 运行时（Win10/11 一般自带）
  注意：本版本是精简版（framework-dependent），换到没装 .NET 10 的电脑上会打不开。

【数据位置（不随程序移动而丢失）】
  %APPDATA%\TodoCalendar\
  ├─ todos.json       ← 待办数据（AI / MCP 读取的权威文件）
  ├─ todos.json.bak   ← 上一次写入前的自动备份
  ├─ window-state.json
  └─ import-result.json（仅 --import 批量导入时产生）
浏览器缓存（可清理）：
  %LOCALAPPDATA%\TodoCalendar\WebView2\
前端页面（宿主自动解包，改它会在下次启动被覆盖）：
  %LOCALAPPDATA%\TodoCalendar\web\index.html

【AI 连接（可选）】
程序会把待办镜像到 %APPDATA%\TodoCalendar\todos.json；
配合 WorkBuddy 的 todocalendar MCP 连接器，AI 即可读取 / 修改待办。

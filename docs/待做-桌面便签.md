# 待做需求：今日待办便签（桌面悬浮）

> 状态：**已记录，暂不实现**（2026-10-27 定稿，用户决定先做别的）
> 实现时先读本文末尾「开工前必须先确认」三条。

## 1. 需求定位

桌面上常驻一张「今天要做什么」的便签，默认待在桌面层不打扰；用户主动点它时才浮到最前并高亮。

关键词是**不打扰**：不抢焦点、不进 Alt+Tab、不出现在任务栏，任何正在用的窗口都在它上面。

## 2. 层级模型（核心）

| 层级 | z 序 | 内容 | 便签行为 |
|---|---|---|---|
| 置顶层 | 最高 | 点击后的便签 | 盖住当前应用窗口，加描边高亮 |
| 应用层 | 中 | 浏览器 / 企业微信 / IDE… | 永远盖住便签 |
| 桌面层 | 最低 | 壁纸之上（WorkerW） | **便签默认所在** |

## 3. 功能需求

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-1 | 内容构成：标题 `10月27日 周二`；今日待办条目（标题 + 截止提示）；底部 `4 项 · 已完成 1 项` | 条数、排序与主程序一致 |
| FR-2 | 桌面态：默认置底，被其他窗口遮挡，不抢焦点、不显任务栏、不进 Alt+Tab | 打开浏览器后完全不可见 |
| FR-3 | 点击提升：单击 → 升至当前应用之上，加 1.5px 主色描边 + 外发光环 | 点击后完全可见，描边生效 |
| FR-4 | 退出置顶：再点一次 / Esc / 点击其他窗口 / 10 秒无操作 | 四种方式都能回落到桌面态 |
| FR-5 | 置顶态可交互：滚轮滚动、点击条目打开主程序并定位、点圆圈勾选完成 | 勾选后主窗口 30 秒内同步 |
| FR-6 | 数据同源：读 `%APPDATA%\TodoCalendar\todos.json`，30 秒或文件变更刷新 | 主程序改数据后便签自动更新 |
| FR-7 | 开关与记忆：托盘菜单「显示桌面便签」；记住位置/尺寸/开关，开机自启按上次状态恢复 | 重启后位置不变 |

## 4. 状态机

```
隐藏态 ──(托盘开启)──▶ 桌面态 ──(单击)──▶ 置顶态
                         ▲                  │
                         └──(再点/Esc/失焦/10s)──┘
```

三个状态都持久化，杀掉进程重开能还原到上次状态。

## 5. 边界与例外

| 场景 | 期望行为 |
|---|---|
| Win + D 显示桌面 | **便签应出现**（这正是它最有用的时刻） |
| 全屏应用（PPT 放映 / 游戏 / 视频） | 便签不出现，也不弹到全屏层之上 |
| 资源管理器重启 | 桌面层失效，5 秒内自动重建，不能彻底消失 |
| 多显示器 / 缩放 125% / 拔插外接屏 | 位置按工作区校正，越界拉回（可复用主程序 `FitInside`） |
| 无今日待办 | 显示「今天没有安排」或自动隐藏（待定，见第 9 节） |
| UAC 提权窗口在前台 | 系统限制，不视为缺陷 |

## 6. 技术方案与风险

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| A 真桌面层 | `SetParent(便签, WorkerW)` | 字面最符合「仅桌面层」 | explorer 重启失效；Win11 的 WorkerW 结构与 Win10 不同；**WebView2 运行中换父窗口易白屏/崩溃** |
| B 压底 | 普通窗口 + `WS_EX_NOACTIVATE` + `WS_EX_TOOLWINDOW`，定期 `SetWindowPos(HWND_BOTTOM)` | 稳定，不换父，WebView2 不受影响 | 不是真桌面层，Win+D 行为略有差异 |

**建议选 B**：便签必然复用主程序那套 HTML/主题，就得走 WebView2，而重父化是它的已知薄弱点。视觉结果与 A 几乎一致。

如果非要做 A，需要准备非 WebView2 的降级渲染（GDI 画或静态位图），不建议。

## 7. 非功能需求

- 常驻内存增量 < 40 MB（第二个 WebView2 实例的实际量级）
- 空闲 CPU < 0.3%（压底轮询间隔 ≥ 2 秒）
- 不影响主程序启动时间（延迟 3 秒拉起或独立进程）
- 数据不出本机；便签上不显示备注等敏感长文本

## 8. 验收标准

| # | Given | When | Then |
|---|---|---|---|
| 1 | 便签在桌面态，浏览器已最大化 | 观察 | 便签完全不可见 |
| 2 | 便签在桌面态 | 点击便签 | 便签盖住浏览器，描边出现 |
| 3 | 便签在置顶态 | 按 Esc | 回落到浏览器之下 |
| 4 | 便签在桌面态 | 按 Win + D | 便签随桌面一起显示 |
| 5 | 便签有任何待办 | 在主程序给该任务打勾 | 30 秒内条目消失、计数更新 |
| 6 | 便签已调整位置 | 重启程序 | 位置与开关状态还原 |

## 9. 开工前必须先确认

1. **内容口径**：只放「今天到期」，还是把「进行中的跨天任务、逾期任务」也纳入？
   （建议后者，否则 7 天的长任务中间几天便签是空的）
2. **无待办时**：显示「今天没有安排」，还是自动隐藏？
3. **置顶态能否勾完成**：能勾最方便，但会让「提升」从「看一眼」变成「操作」，可能破坏不打扰的定位。

## 10. 范围外（本版不做）

便签内新建/编辑完整任务（只读 + 勾选）、多个便签、跨设备同步、便签自身推送提醒（复用现有托盘提醒）。

## 11. 可复用的现有资产

- 数据：`%APPDATA%\TodoCalendar\todos.json`（与主程序同源，已有 mtime 轮询机制）
- 时间与进度计算：`winapp/Reminder.cs`（`StateOf` / `HumanLeft` / `Span`，已处理逾期与剩余时长文案）
- 视觉：`todo.html` 里 `--card / --line / --accent / --text-dim` 等变量，跟随浅色/深色
- 窗口位置校正：`MainForm.FitInside`
- 托盘与开机自启：`SetupTray` / `SetAutostart`（自启注册表已带 `--tray`，便签可复用同一入口）
